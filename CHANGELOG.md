# Changelog

All notable changes to this project are documented in this file.
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.0.0] - 2026-11-17

First release of the v1 pipeline: one command runs every stage of the manuscript's analysis from one configuration file, the manuscript's layers are reproduced by configurations and tests, trained SAEs are exported for the Hugging Face Hub, and a CPU tutorial runs the spatial stages from a published SAE.

### Added

- v1 pipeline core: the `interpretfm` command (`validate`, `run`, `status`, `report`, `version`), a typed YAML configuration (`run`, `dataset`, `model`, `stages`, `output`) with the spatial unit declared once as `dataset.spatial.um_per_unit`, a cached and resumable stage runner with `--stages`, `--force` and `--dry-run`, run and stage `manifest.json`, a subprocess boundary to per-model conda environments, the `ingest` stage, stubs for the remaining stages, toy fixtures (`interpretfm.testing`) and `configs/toy.yaml`.
- Documentation pages for the configuration, running a pipeline and the run directory; API page for the pipeline core.
- Model-level stages of the v1 pipeline: `tis` (TIS with shuffled and PCA controls), `sae` (the biased ReLU SAE trainer with the fixed resampler, QC, the λ rule and the untrained baseline), `concepts` (g:Profiler concept universe with cache, an offline matrix mode and configurable gene keys), `concept_eval` (held-out concept F1 under the row and whole-gene splits for SAE, raw and untrained units, with cell de-duplication) and `gene_readout` (gene-level linear readout with expression and random controls); the stage order gains `concept_eval` and `gene_readout`. Shared helpers `interpretfm.stores` (activation-store reading, cached stores through `store_root`), `interpretfm.genes` (gene keys, token vocabularies) and `interpretfm.params`; `write_toy_run(store=True)` writes a synthetic activation store. One documentation page per stage.
- Cell-level stages and the report of the v1 pipeline: `ingest` now checks raw counts, gene names, labels and coordinates, flags low-quality cells (`dataset.qc`, defaults 20 transcripts / 10 genes; kept, never dropped), reports the panel's coverage of the model vocabulary (`model.vocab`) and writes a cell table in µm; `cells` (feature retention by the fixed rule, projection of features to cells, GSI excess and MHR@k for SAE features, raw dimensions and single genes on the same cells); `layers` (per-criterion layer table with baselines and best-layer notes, no composite score); `report` (`report.json` with every metric beside its baseline and one self-contained HTML page), wired to `interpretfm report`. Helpers `interpretfm.ingest`, `interpretfm.cells`, `interpretfm.layers`, `interpretfm.report`.
- Manuscript configurations for the six representative layers (`configs/paper/`), starting from the cached activation stores and SAE checkpoints and naming data only through `${INTERPRETFM_*}` placeholders (`configs/paper/paths.env.example`); reproduction tests (`tests/reproduction/`, marker `reproduction`, skipped unless the data are configured) for TIS gain, the λ rule and untrained baseline, concept F1 under both held-out units, concept counts and the gene-level readout, with placeholders for the cell-level and spatial numbers; `make repro`/`repro-test` and the documentation page "Reproducing the manuscript".
- Spatial niches (`niches` stage, replacing the `spatial` stub; skipped for data without coordinates): the manuscript's niche sweep (radii in µm converted through `dataset.spatial.um_per_unit`, k-means / GMM, `m` / `xm`, seeds, minimum cluster size, the score 1.5 ARI + 0.1 clip(z) + separability) with validation (purity against the tile-shuffle null, ARI/NMI against the labels), the expression-only (truncated SVD) and label-composition (scikit-learn, no squidpy) baselines at their own winner and at the model's configuration, optional expression preprocessing variants, seed stability, and niche concept labels (Wilcoxon inside vs outside, BH, top 25 by effect) with a cross-model Jaccard recipe; `interpretfm.niches`, `interpretfm.niche_concepts`; the niche numbers beside their baselines in `report.json` and the HTML page; the `cells` and `niches` sections of the paper configurations; reproduction tests T6-T9 and T13.
- Calibrated cell–cell interface test (`interfaces` stage, between `niches` and `report`; skipped for data without coordinates): the manuscript's strict crosstalk statistic on the program score adjusted for counts, genes and cell area within the exact label, with the within-block × niche × label permutation null, the smooth-field calibration of the call threshold `z*`, the legacy uncalibrated tile null beside it, the niche-free variant, effect sizes, partner markers and the fired-on genes of every feature; library recipes for the partner-marker tercile check and the marker-excluded (spillover-robust) re-test over several models (`interpretfm.interfaces`); the interface numbers beside their baselines in `report.json` and the HTML page; `dataset.labels.file` (per-cell label CSV), `dataset.labels.groups` / `group_map` (label groups) and the `group` column of the ingest cell table; the `interfaces` sections and the CosMx author-type group map of the paper configurations; reproduction tests T10 (three models) and the tercile / marker-excluded checks.
- Model-free ligand–receptor co-localization screen (`lr_screen` stage, between `interfaces` and `report`; skipped for data without coordinates): the manuscript's panel-wide screen on CellChatDB human pairs with every gene on the panel (complexes resolved to subunits), positivity at ≥ 1 and ≥ 3 transcripts, within-type permutation null with the reference's draw order, fold / z / BH q, hit, robust-hit and depleted rules, the radius in µm or matched to a target mean number of other cells within the radius (`match_neighbors_to`), and the niche placement of the hits (share of close pairs per niche over the niche's share of cells, cell-type pairs); `interpretfm.lr_screen`, `interpretfm.neighbours` (`mean_other_cells`, `radius_curve`, `match_radius`, with the cross-section matching recipe); the two CellChatDB tables shipped as package data (`interpretfm/data/cellchatdb/`, GPL-3, with `NOTICE.md`) and `database` / `complexes` overrides; the `lr_screen` sections of the paper configurations; reproduction tests T11 (the screen at the paper's and at the matched radius) and T12 (matched-neighbour radii of both sections).
- Full HTML report: `interpretfm.report` is a package (`metrics` for `report.json`, `html` for the page) rendering a Jinja2 template (`jinja2` is a dependency) with every section beside its baselines — layer summary (TIS with its controls, concept F1 sparse / raw / untrained on both splits, readout), cell specificity (GSI / MHR against raw dimensions and single genes with chance), niches (ARI / NMI against the expression-only and label-composition partitions, tile null, seed stability), interfaces (legacy tile against calibrated |z| > 2 shares, z*, false-positive rates, calls, effect sizes), the ligand–receptor screen (hits at both thresholds, robust hits, niche placement) — new figures for the niche, interface and screen sections, and a "how to read" note per section (`section_notes` in `report.json`); stages that did not run render as "not run".
- Reproduction of the five other paper layers (CosMx Geneformer `layer_1`, CosMx C2S-Scale `layer_13`, Xenium scGPT `layer_2.norm2`, Xenium Geneformer `layer_1`, Xenium C2S-Scale `layer_13`): `tests/reproduction/test_other_layers.py` (T6–T13 from the caches and the run directories; the Xenium five-niche partitions, the marker-label interface test and ligand–receptor screen, the cross-model concept recipe for every model pair), the published numbers in `expected.py`, and the six-layer table in "Reproducing the manuscript".
- Per-stage label sets: `stages.<niches|interfaces|lr_screen>.labels` takes the keys of `dataset.labels` (`column`, `file`, `file_column`, `groups`, `group_map`) and replaces the dataset labels for that stage (`interpretfm.ingest.stage_labels`; `interpretfm.config.parse_labels`). The Xenium paper configurations use it for the marker-derived labels of `xenium_marker_labels.csv.gz` (niches, interfaces, screen) while the cell-level stages keep the dataset's `cell_type` column, as in the manuscript; they list the five-niche configuration of each model as the first fixed configuration and place the interface test and the screen on it.
- Parallel concept evaluation: `stages.concept_eval.n_jobs` runs the evaluations (unit × representation) in separate processes through the same function as the sequential path (identical tables; toy test), `threads_per_job` sets their torch threads; both are left out of the stage hash through the new `register_stage(hash_ignore=...)`. The paper configurations use `n_jobs: 6`.
- Cross-model niche concept recipe: `interpretfm.niche_concepts.read_niche_run` and `cross_model_concepts` (composition matching and top-concept Jaccard for every pair of finished runs).
- `${NAME}` placeholders in configuration strings, filled from the environment or a `KEY=VALUE` file (`--env-file`, `load_config(env_file=...)`, `interpretfm.config.load_env_file`).
- Activation extraction across the model-environment boundary: the `extract` stage extracts scGPT and Geneformer activations through `interpretfm.models` adapters (`scgpt`, `geneformer`, the synthetic `toy` model; `c2s_scale` below) in the model's own environment as a child process (`python -m interpretfm.cli extract --config ... --run-dir ... --model ... --layers ...`), with the batch size, dtype, shard size, device and an optional seeded or listed cell subset from `stages.extract`, the gene key from `dataset.gene_id` (scGPT symbols, Geneformer Ensembl ids, with the package's gene-name dictionary for symbol-keyed panels) and the cell pooling from `model.cell_pooling`; per-layer `02_extract/<layer>/manifest.json` records rows, cells, tokens, vocabulary coverage and the child's interpreter, torch/CUDA versions and installed packages. `model.env: {}` runs the stage in-process; a cached store (`store_root`) never needs the model environment. `model.env: {container: <image>}` runs the child with Apptainer/Singularity/Docker/Podman and binds the run directory and data paths (runtime path not exercised yet). `interpretfm.extract.compare_stores` / `compare_projections` compare two stores cell by cell (token order, per-token cosine, absolute and relative differences, SAE-projected cell features); `configs/paper/extract_cosmx_{scgpt,geneformer}.yaml` and the GPU reproduction test `tests/reproduction/test_extraction.py` (`INTERPRETFM_REPRO_GPU=1`) reproduce the manuscript's stores on 2,000 cells (identical token sequences, per-token cosine ≥ 0.9999995). Container files in `containers/` (three Dockerfiles, an Apptainer definition, a manual GitHub Actions build workflow; builds not tested locally); `envs/README.md` and the installation page describe the per-model installs and weights; documentation page for the extract stage.

- Hugging Face export and loading of trained SAEs (`interpretfm hub export <run_dir…> <out_dir>`, `interpretfm hub verify`; `interpretfm.hub.load_sae`, `load_features`, `layer_dir`, `tutorial_bundle`): one folder per model, dataset and layer with the weights as safetensors, `config.json`, the retained feature–concept table, `metrics.json` with every metric beside its baseline and a model card; the optional extra `hub` (`safetensors`, `huggingface_hub`).
- Tutorial `docs/tutorials/cosmx_crop.ipynb` (CPU, Colab or local): the spatial stages `niches`, `interfaces`, `lr_screen` and `report` on a crop of the public CosMx section from the published scGPT SAE and its projected features, with the data bundle loaded from a local folder or the Hugging Face repository; an optional GPU section for scGPT extraction. Stages accept published projected features in place of the `cells` stage (`cells_h5ad`, now also satisfying the runner's input check) and `stages.report.spatial_only` builds the report from the spatial stages alone.
- Installation guide: "Which environment do I need?" (core environment for every stage after extraction, per-model environments or containers for extraction only, the forms of `model.env`); README quick start for the pipeline; `RELEASE.md` with the release steps.
- C2S-Scale extraction through the same boundary (`interpretfm.models.c2s_scale`, `model.name: c2s_scale`, `envs/c2s.yml`): the cell2sentence cell sentence of every cell (detected genes by descending count, upper-cased symbols, at most `max_genes`; ties broken by a shuffle seeded with `tie_seed` plus the cell's position within its shard, taken from the whole dataset so that a cell subset does not change the sentences; the vendored cell-type-prediction prompt with the dataset's organism), the hidden state of each gene's last sub-token (`token_pooling`) pooled in float32 and stored as float16 rows, the model in `model_dtype` (float32), shards from an `obs` column (`shard_column`) or consecutive blocks; adapters get a `prepare()` hook that sees the whole dataset before the subset. `configs/paper/extract_cosmx_c2s.yaml` and the GPU test `tests/reproduction/test_extraction_c2s.py` reproduce the manuscript's CosMx C2S-Scale store on the same 2,000 cells (identical token sequences, per-token cosine ≥ 0.999999, one float16 step at most from batch composition; bit-identical in the original batches). `INTERPRETFM_C2S_ENV` / `INTERPRETFM_C2S_MODEL` placeholders.
- Trained SAEs of the six manuscript layers on the Hugging Face Hub (`YunfeiHu/interpreTFM`, the default repository of `interpretfm.hub`); the C2S-Scale model cards credit the C2S-Scale weights (CC BY 4.0) and carry the Gemma notice.
- `interpretfm.hub.tutorial_crop`: the tutorial's CosMx crop is built locally from the public Nicheformer release file (`theislab/SpatialCorpus-110M`, pinned revision, checked against the manuscript crop's digest); the Hugging Face tutorial files are derived files only.
- Reproduction tests: `expected.KNOWN_DIFFERENCES` lists the printed values that the pipeline does not reproduce within tolerance, with the printed and the pipeline's value (also in "Reproducing the manuscript"); such a comparison is reported, and every other comparison of the same test is still asserted.
- Randomly re-initialized models: `stages.extract.weights` (`trained`, `random_table`: every parameter re-initialized except the trained gene-embedding table, `random_all`: every parameter re-initialized) and `weights_seed` for scGPT and Geneformer (`interpretfm.models.reinit`; each module's own initialization, on the extraction device; an error for C2S-Scale); the setting is recorded in the layer manifests and, for a cached store, in `store.json`. `interp_pipeline.extraction.geneformer_extraction.extract_geneformer_to_store` takes an `after_load` hook. Configurations `configs/paper/reinit_cosmx_{scgpt,geneformer}_{trained,random_table,random_all}.yaml` (CosMx Layer 2, the GSI/MHR cell sample shipped as `cosmx_<model>_sample_cells.txt.gz`; the five λ, the λ rule and concept F1 on both held-out units from the cached stores and checkpoints).
- Post hoc controls of the gene-level readout (`gene_readout`): the gene-symbol controls `names_tri` (binary character-trigram profile of each symbol) and `names_pc50` (its first 50 principal components); `symbol_residuals`, representations scored with their `names_pc50`-predictable part removed (least squares fitted on each split's training genes); `stores`, further stores of the same model scored by their mean hidden states; `representations`; `universe`, a gene list; `split.first_from`, a held-out gene split as split `s0`. Configurations `configs/paper/readout_controls_<layer>.yaml` for the six representative layers (the genes observed by all three models, `{cosmx,xenium}_readout_genes.txt`, and the manuscript's five splits; the re-initialized scGPT and Geneformer stores for CosMx).
- Reproduction tests `tests/reproduction/test_post_hoc_controls.py`: the λ rule and concept F1 of the re-initialized models from the cached tables and from the pipeline runs, the shipped cell lists against the cached stores, re-initialization and extraction of 40 cells against the cached stores (GPU), the readout controls against Supplementary Table S3 and the cached results, and the readout code on the manuscript's cached per-gene mean hidden states; `INTERPRETFM_REINIT_CACHE` and `INTERPRETFM_POSTHOC_CACHE` in `paths.env.example`.
- `stages.extract.cell_subset` reads gzip-compressed cell lists (`.gz`).

### Changed

- `envs/interpretfm.yml` lists the manuscript environment's versions of the packages interpreTFM uses and their dependencies instead of the whole exported installation (some of the research-only packages' pinned wheels are no longer on PyPI); `nnsight` is installed separately with `--no-deps` for scGPT extraction.
- `interfaces`: partner markers are computed for labels with at least two cells (a single-cell label no longer stops the stage).
- Version 1.0.0; `pyyaml` and `jinja2` are dependencies.
- The TIS PCA control defaults to `pca_of: activations` (the activations rotated to their principal components, the control the manuscript reports); `pca_of: expression` remains available.
- Stage hashing: `dataset.labels` (column, file, groups, group map) enters a stage's configuration hash only when the stage declares `uses_labels=True` at registration (`ingest`, `gene_readout`, `cells`, `layers`, `niches`, `interfaces`, `lr_screen`, `report`), so that a label-only change no longer invalidates the cached extraction, TIS, SAE and concept-evaluation results. Run directories written by earlier development runs show the old hash for those label-free stages; their cached results are revalidated by status only (`interpretfm status`, `make repro-test`), and a plain `interpretfm run` would recompute them, so select stages with `--stages`.
- The `report` stage directory is `13_report` (`12_lr_screen` precedes it).
- `interp_pipeline.adapters.models.c2s_scale.C2SScaleAdapter` takes a `torch_dtype` option (also `interp_pipeline.vendor.c2s_local.load_model.load_c2s_model`) and yields batches from prompts rendered by the caller (`batches_from_prompts`); `make_batches` is unchanged.
- A relative `stages.extract.cell_subset` path is resolved against the configuration file's directory when the configuration is loaded (so that the extraction in the model environment finds it).
- `interp_pipeline.adapters.models.scgpt.ScGPTAdapter` accepts the manuscript's layer names (`layer_<i>.norm2`), takes the gene symbols as an argument, runs the encoder blocks one by one with the padding mask (as the extraction that wrote the manuscript's store did) and no longer stores padding rows; `extract_activations` takes a storage dtype (`save_dtype`).

## [0.9.0] - 2026-11-05

First public pre-release of the analysis package.

### Added

- Documentation site (Sphinx, Read the Docs): installation, concepts, data formats, usage, evaluation best practices, roadmap, FAQ and API reference.
- Package metadata (`interpretfm` distribution, version 0.9.0), optional extras `models`, `annotation`, `docs` and `dev`.
- Held-out concept alignment with row and whole-gene splits, including optional de-duplication of cells that appear more than once in an activation store (`dedup_cells`, `--f1-dedup-cells`).
- Example model specification for the all-layer runner (`configs/model_specs.example.json`).
- CPU tests that need no data: imports, command-line help, the quick-start examples on toy data, and held-out F1 regressions.
- Continuous integration (tests and documentation build), pre-commit configuration, contribution guide, code of conduct, security policy, citation file and third-party notices.
